# План реализации v0.1.0

Источник бизнес-правил — [спецификация MVP](mvp.md).
Этот файл сохраняет порядок работ для разработки в IntelliJ IDEA, облачной среде
и новой сессии Codex CLI.

## Текущее состояние

- Стартовый Kotlin/Spring Boot-каркас подготовлен.
- Этап 1 выполнен на уровне спецификации; сценарии приёмки ещё требуют реализации.
- Этапы 2–12 запланированы. Наличие их описания не означает готовности функциональности.

## Порядок разработки

Этап делится на небольшие задачи и pull request. Для каждой задачи указываются
затрагиваемые правила и сценарии приёмки из `mvp.md`.
Тесты добавляются при реализации поведения; этап 10 объединяет проверку гарантий
и добавляет проверки конкуренции, сбоев и нагрузки.

Финансовые команды используют единый механизм учёта. Изменение бизнес-правила
сопровождается обновлением спецификации и соответствующих проверок.
Технические решения внутри этих границ выбираются при реализации этапа.

## Следующий этап: основа приложения

1. Разделить код по функциональным модулям, сохранив корневой пакет
   `com.kamerzing.payment_core` и стартовый класс.
2. Ввести единый контракт ошибок `ProblemDetail` с `code` и `traceId`.
3. Настроить GitHub Actions на JDK 21 и сборку через Gradle Wrapper.
4. Подтвердить сборку и тест загрузки контекста.
5. Сохранить статус реализации и команды проверки в документации.

PostgreSQL, миграции и денежные эндпоинты выполняются в своих этапах.

## Приёмка выпуска

Создать двух пользователей и их кошельки; выполнить административное пополнение,
перевод и повтор запроса; проверить единственный денежный эффект; выполнить
возврат получателем; проверить историю и сверку. После перезапуска приложения
проверить сохранность данных. Резервную копию восстановить в отдельную БД
и повторить сверку.
