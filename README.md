# Payment Core

Учебное платёжное ядро на Kotlin и Spring Boot: рублёвые кошельки,
тестовые пополнения, переводы и полные возвраты с журналом денежных проводок.
Все суммы в API и базе данных выражаются целым числом копеек.

## Состояние проекта

Подготовлен стартовый Spring Boot-каркас: приложение, Actuator и тест загрузки
контекста. Этап 1 фиксирует правила MVP и критерии приёмки в документации.
Пользователи, PostgreSQL и денежные операции относятся к следующим этапам.

- [Спецификация MVP](docs/mvp.md) — роли, денежные правила, API, ошибки и сценарии приёмки.
- [План реализации](docs/implementation-plan.md) — этапы и условия их завершения.

Описанные в спецификации бизнес-эндпоинты являются целевым контрактом `v0.1.0`.
Сейчас из перечисленных возможностей приложения доступна проверка Actuator.

## Локальная сборка и запуск

Установите полный JDK 21 и откройте корневой каталог проекта в IntelliJ IDEA.
Для текущего каркаса база данных и секреты не требуются.

Linux / macOS, из корня проекта:

```bash
sh gradlew build
sh gradlew bootRun
```

Windows PowerShell, из корня проекта:

```powershell
.\gradlew.bat build
.\gradlew.bat bootRun
```

`build` запускает существующие тесты и собирает приложение. `bootRun` работает
до остановки через `Ctrl+C`. При стандартной конфигурации приложение слушает
порт `8080`; запрос `GET /actuator/health` должен вернуть HTTP `200`
и JSON с `"status": "UP"`.

Настройки прокси конкретной среды передаются вне исходников. Пароли, ключи
подписи токенов и другие секреты передаются через защищённую конфигурацию.

## Продолжение разработки

Перед задачей прочитайте спецификацию MVP и план реализации. Следующая работа —
структура модулей, обработка ошибок и CI, затем PostgreSQL и миграции.
Тесты поведения добавляются вместе с реализацией соответствующих сценариев.

Целевое развёртывание: одно приложение, PostgreSQL и HTTPS-прокси на Linux-сервере
с квотой 4 vCPU, 2 ГБ RAM и 100 ГБ диска. Сборка и интеграционные тесты выполняются
локально или в CI; на сервер доставляется готовый образ. Потребление ресурсов
проверяется нагрузочным тестом перед выпуском.
